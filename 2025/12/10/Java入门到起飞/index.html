2.6.数字的加密解密

需求：
​某系统的数字密码（大于0），比如1983，采用加密方式进行传输。
规则如下：
​先得到每位数，然后每位数都加上5，再对10求余，最后将所有数字反转，得到一串新数。

每位数字的加密过程：

0-4 +5 5-9 %10 5-9
5-9 +5 10-14 %10 0-4

每位数字的解密过程：

5-9 不变 5-9 -5 0-4
0-4 +10 10-14 -5 5-9

![[Java/Java基础/第1阶段—Java基础/3、Java入门到起飞/draw/数字的加密解密|数字的加密解密|420]]

加密时，+5 再 %10 两步一起的规律是：

  • 小的个位数 +5 变为大的个位数，大的个位数 %10 结果不变，加密的结果是大的个位数
  • 大的个位数 +5 变为小的十位数，==小的十位数== %10 只保留个位数，等价于 -10，加密的结果是小的个位数

所以解密时，%10 的逆运算，这个不容易直接确定的一步的规律是：

  • 大的 个位数 %10 的逆过程是 不变
    • 小的个位数 +5 得到大的个位数，对十取余后结果不变
  • 小的 个位数 %10 的逆过程是 +10
    • 大的个位数 +5 得到小的十位数，对十取余相当于 -10

金额转换

除数和被除数

除法运算的目的是确定被除数（a）被除数（b）等分多少次：

  • 被除数（Dividend）：被分割的总数量。例如，在表达式 a ÷ b 中，a 是被除数；
  • 除数（Divisor）：分割时每份的数量。例如，在表达式 a ÷ b 中，b 是除数；
  • 商（Quotient）：除数把被除数分成多少等份；
  • 余数（Remainder）：除数把被除数等分时，无法完全均分时剩下的部分。

除法运算可以用以下方式表示：
a ÷ b = c … r

  • a 是被除数。
  • b 是除数。
  • c 是商，表示被除数被除数均分的次数。
  • r 是余数，表示被除数无法完全均分时剩下的部分。
    例如，10 ÷ 3 = 3 … 1 表示被除数 10 被除数 3 均分了 3 次，余下 1。

质数

质数是指大于1的自然数，除了1和它本身以外，不能被其他自然数整除的数

[!info] 自然数
术语“自然数”源自对人类最早接触的数字概念的称呼，即从最简单的计数开始的数。它们是最基本的数字概念，因为人类最初的数学发展是从物理世界的计数开始的，比如计数物体、人、动物等。
在古代数学和哲学中，自然数被视为最基本、最直观的数学概念，它们自然而然地呈现在人类日常生活和观察中。因此，“自然数”一词中的“自然”意味着它们是在人类生活和观察的自然界中最直接、最基本的数字概念。

不能被其他自然数整除的数。除和除以的区别：

  • ‘被除数’除以’除数’

  • ‘除数’除’被除数’，比如：’检查从 2 到 sqrt(num) 之间的整数能否整除 num‘

  • ‘被除数’被’除数’除，比如：质数不能被其他自然数整除。

  • 要判断 num 是否为质数，只需检查从 2 到 sqrt(num) 之间的整数能否整除 num。

  • 质数（素数）是指除了1和本身之外，没有其他正因子的自然数。

  • 如果 num = a * b，a,b 是 num 两个成对的因子

    • 如果 a<=sqrt(num)，则 b>=sqrt(num)
    • 如果没有 <=sqrt(num) 的因子，也就没有>=sqrt(num) 的因子
    • 所以判断质数只要找有没有 <=sqrt(num) 的因子。

Copies an array from the specified source array, beginning at the specified position, to the specified position of the destination array. A subsequence of array components are copied from the source array referenced by src to the destination array referenced by dest. The number of components copied is equal to the length argument. The components at positions srcPos through srcPos+length-1 in the source array are copied into positions destPos through destPos+length-1, respectively, of the destination array.
If the src and dest arguments refer to the same array object, then the copying is performed as if the components at positions srcPos through srcPos+length-1 were first copied to a temporary array with length components and then the contents of the temporary array were copied into positions destPos through destPos+length-1 of the destination array.

冒泡排序

外循环遍历右侧已排序区间的长度，内循环遍历左侧未排序区间的两个待比较元素的第一个索引。
i < arr.length-1

  • i 表示右侧已排序元素个数
  • 开始 i = 0，表示已排序元素的个数是 0
  • 最后 i = length - 1，表示还剩 1 个未排序元素，结束循环
  • 每循环一次排好一个元素，循环 length - 1 次
    j < arr.length - 1 - i
  • 确定了已右侧已排序区间的长度，就能知道左侧未排序区间的右边界。
  • 右闭的边界减去区间个数等于左开的边界，右侧已排序区间的左开的边界等于左侧未排序区间右闭的边界
  • arr.length - 1 是数组的右边界，减去右侧已排序区间的个数 i，就是左侧未排序区间的右边界
  • 索引 j 要小于未排序区间的右边界，才能让索引 j+1 不超过右边界

Swap while Selecting

每次遇到更小的元素，都进行交换

  • 上面的冒泡是每次把未排序区间内的最大的元素冒泡到最右边
  • 这里的选择是每次选出未排序区间内的最小的元素放到最左边
    外层循环：
  • i 代表未排序区间的左边界，也是已排序的元素个数
  • 开始时左侧没有已排序区间，所以 i 从数组顶头开始
  • i = arr.length - 1，未排序区间只剩下一个时就不用排了
    内层循环：
  • 默认 i 位置的元素是最小值
  • 从 i+1 开始找，如果比 i 位置的元素更小，则交换这两个位置的元素
  • 交换后，相对更小的元素就放在了 i 位置上
  • 让 i 上的更小值继续和无序区间的下一个元素比较

Select then Swap

选择完了后再交换，选出当前未排序区间所有元素中最小的后，再交换到当前未排序区间的最左侧

插入排序

减少元素交换带来的赋值操作：

  • 上面是通过相邻两元素交换来把待插入元素一步步地交换到有序区间的合适位置，没找到最终插入位置前，每次都把可能的插入位置赋值为插入元素，这可能会产生很多多余的赋值操作；
  • 优化后是，先把有序区间比待插入元素大的都向后移动一下，空出待插入位置，再直接插入。

快速排序

基准数归位，每次让基准数存到数组有序后的正确位置
右指针是从后向前找比基准数小的，先移动右指针，能保证两个指针相遇时，指针所指向的值是小于基准数的。有两种相遇的情况：

  1. 移动左指针时。
    • 右向指针先停在了小于基数数的值上，再移左指针，左指针也会停在这个值上
  2. 移动右指针时；
    • 左指针指向的是基准数，或者指向的是左右交换后的小于基准数的值的索引

两种比较方式小结

  • 自然排序: 自定义类实现Comparable接口，重写compareTo方法，根据返回值进行排序
  • 比较器排序: 创建TreeSet对象的时候传递Comparator的实现类对象，重写compare方法，根据返回值进行排序
  • 在使用的时候，默认使用自然排序，当自然排序不满足现在的需求时，必须使用比较器排序
  • 两种方式中关于返回值的规则
    • 如果返回值为负数，表示当前存入的元素是较小值，存左边
    • 如果返回值为0，表示当前存入的元素跟集合中元素重复了，不存
    • 如果返回值为正数，表示当前存入的元素是较大值，存右边

[!quote] 自然排序

  1. 内在属性： 自然排序的逻辑通常是基于该类内在的、最核心的属性或特征来定义的。例如：
    Integer 类的自然排序是按照数值大小升序排列。
    String 类的自然排序是按照字典顺序排列。
    Date 类的自然排序是按照时间先后顺序排列。
    这些排序方式通常是人们对这些数据类型的最直观的理解和期望，因此被认为是“自然的”。
  2. 类的本性： 自然排序是类自身的一部分，是类本身就应该具有的一种排序能力。当一个类实现了 Comparable 接口，它就是在告诉外界：“我本身就知道如何比较大小，按照我定义的方式来排序就是最合适的”。
  3. 默认行为： 当一个类拥有了自然排序的能力后，在没有提供其他排序规则的情况下，许多 Java API (例如 TreeSet、TreeMap、Collections.sort()) 都会默认使用这种自然排序。这体现了自然排序的默认性和重要性。
  4. 逻辑一致： 对于同一个类的实例，自然排序的逻辑应该是一致的。也就是说，如果a.compareTo(b) 返回正数，那么 b.compareTo(a) 就应该返回负数。这也符合我们对 “自然” 排序的期望，即它应该是稳定且逻辑自洽的。

线程状态

线程状态 具体含义
NEW 一个尚未启动的线程的状态。也称之为初始状态、开始状态。线程刚被创建，但是并未启动。还没调用start方法。只有线程对象，没有线程特征。
RUNNABLE 当我们调用线程对象的start方法，那么此时线程对象进入了RUNNABLE状态。那么此时才是真正的在JVM进程中创建了一个线程，线程一经启动并不是立即得到执行，线程的运行与否要听令与CPU的调度，那么我们把这个中间状态称之为可执行状态(RUNNABLE)也就是说它具备执行的资格，但是并没有真正的执行起来而是在等待CPU的调度。
BLOCKED 当一个线程试图获取一个对象锁，而该对象锁被其他的线程持有，则该线程进入Blocked状态；当该线程持有锁时，该线程将变成Runnable状态。
WAITING 一个正在等待的线程的状态。也称之为等待状态。造成线程等待的原因有两种，分别是调用Object.wait()、join()方法。处于等待状态的线程，正在等待其他线程去执行一个特定的操作。例如：因为wait()而等待的线程正在等待另一个线程去调用notify()或notifyAll()；一个因为join()而等待的线程正在等待另一个线程结束。
TIMED_WAITING 一个在限定时间内等待的线程的状态。也称之为限时等待状态。造成线程限时等待状态的原因有三种，分别是：Thread.sleep(long)，Object.wait(long)、join(long)。
TERMINATED 一个完全运行完成的线程的状态。也称之为终止状态、结束状态

线程池工作流程

当我们通过submit方法向线程池中提交任务的时候，具体的工作流程如下：

  1. 客户端每次提交一个任务，线程池就会在核心线程池中创建一个工作线程来执行这个任务。当核心线程池中的线程已满时，则进入下一步操作。
  2. 把任务试图存储到工作队列中。如果工作队列没有满，则将新提交的任务存储在这个工作队列里，等待核心线程池中的空闲线程执行。如果工作队列满了，则进入下个流程。
  3. 线程池会再次在非核心线程池区域去创建新工作线程来执行任务，直到当前线程池总线程数量超过最大线程数时，就是按照指定的任务处理策略处理多余的任务。

CyclicBarrier

CyclicBarrier的字面意思是可循环使用（Cyclic）的屏障（Barrier）。它要做的事情是，让一组线程到达一个屏障（也可以叫同步点）时被阻塞，直到最后一个线程到达屏障时，屏障才会开门，所有被屏障拦截的线程才会继续运行。

例如：公司召集5名员工开会，等5名员工都到了，会议开始。我们创建5个员工线程，1个开会线程，几乎同时启动，使用CyclicBarrier保证5名员工线程全部执行后，再执行开会线程。

举例：比如男女双方结婚的时候，需要进行交换结婚戒指。
